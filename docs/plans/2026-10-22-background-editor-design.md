# Site background in the editor — design

Date: 2026-10-22 · Status: implemented (review changes below supersede the original text)

## Goal
Justin can replace the site's background image from `/edit`, see it in the live preview
before saving, and save it as part of the usual draft PR. Decisions were taken on his
standing "go with your recommendations" preference.

## Current state
- `src/resources/custom.css`: `.portfolio-body::before` is a fixed full-viewport layer with the
  hard-coded **pre-blurred** `/images/armored-landscape-blur.webp`, under a glass tint
  (`::after`, 83% dark / 91% light). The pre-blur replaced a live `backdrop-filter`
  because the full-viewport filter glitched during the theme-toggle view transition.
- `scripts/og/generate.mjs` (prebuild) uses the sharp `/images/armored-landscape.webp`.
- Content has no background field.

## Design
1. **Content:** new optional field `site.background` (public path, e.g.
   `/images/uploads/background-x1y2.webp`). Missing → today's landscape. Optional so older
   saved drafts/localStorage still load.
2. **Editor (Profile tab):** a "Background image" picker next to the profile photo, using the
   existing `ImagePicker` with a new kind `"background"`: fit inside 2400×1350, WebP, ≤ 500 KB
   (existing quality ladder), EXIF stripped by the canvas. A "Use default" button resets it.
   Upload path `uploadPath("background", ext)`; image is saved with the draft like the avatar.
   `referencedImages` and `withPendingImages` include it, so it is uploaded on save, shown in
   the preview before save, and deleted from `uploads/` when replaced (default never deleted).
3. **Build:** `scripts/og/generate.mjs` (already prebuild) also writes
   `public/images/generated/background-blur.webp` from the configured background with the
   same recipe as the current file (1600×900 cover, blur σ14, saturate 1.25, q80) and records
   `{ "background": "/images/generated/background-blur.webp?v=<hash>" }` in `src/resources/og.json`
   (renamed concept: generated assets manifest). The OG image uses the configured background.
   Generated blur is gitignored? **No** — committed like `home.jpg`, so `tsc`/dev work without a build;
   CI regenerates it anyway.
4. **Site CSS:** `::before` uses `background-image: var(--portfolio-bg, url(<default blur>))`;
   `layout.tsx` sets `--portfolio-bg` inline on `<html>`/body from the manifest.
   Still a static pre-blurred image → no regression for the theme-toggle flicker fix.
5. **Preview:** the iframe can't run sharp, so `PreviewApp` sets `--portfolio-bg` to the
   sharp image (data URL for unsaved uploads) and adds a class that applies
   `filter: blur(14px) saturate(1.25)` and `inset: -40px` to `::before` (hides blurred edges).
   This only affects the preview iframe. Restores the default when the field is cleared.

## Error handling
- Bad file / too large → existing ImagePicker messages.
- Build: a bad or missing background **fails the build in CI** (Pages keeps the previous site live);
  local builds warn and use the default. Restart `npm run dev` after hand-editing `site.background`.
- Validation: `site.background`, if set, must match the lowercase `/images/…` path rule; `""` means default.

## Testing
- Unit: `referencedImages` includes background; `computeChanges` uploads a new background and
  deletes a replaced upload but never the default; `withPendingImages` swaps it; validation.
- Build: generator output exists, manifest updated, CSS var in exported HTML.
- Browser: upload Justin's image in the editor against the fake GitHub, confirm the preview
  background changes (both themes), save, confirm the PR contains site.json + image.

## Changes after plan review
- Path rule `^/images/[\w\-/]+\.(webp|jpe?g|png)$` (no `..`, quotes, brackets, spaces); CSS values are quoted.
- Build **fails in CI** on a bad/missing background (Pages keeps the previous site); local builds warn and use the default.
- Reuses the `cover` image kind (fit 1600×1200) instead of a new 2400px kind.
- Generated blur is **gitignored** and regenerated by `prebuild`/`predev`; `og.json` keeps its name and gains `background`.
- One default (`DEFAULT_BACKGROUND`), duplicated in `scripts/og/background.mjs` with a test that they match; the old committed blur file is removed.
- Background var is set by a `<style>` in `<head>`; the preview-only CSS blur is scaled to the iframe (14px × viewport/1600) and scoped to `html.is-preview.preview-bg`.
- "Use default" deletes the field. Tests cover validation, referencedImages, preview swap, upload/replace/reset/shared-with-avatar deletes, rebase, and the build resolver.
